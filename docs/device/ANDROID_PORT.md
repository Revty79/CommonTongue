# Android MADLAD research port and licensing

The primary artifact remains Google MADLAD400-3B-MT revision `fa184c675da0b5c9e1c8694fccd4e12e2d422094`, `model-q4k.gguf`, **1,654,597,280 bytes**, SHA-256 `ea6e5531a3e95213c7f0635988d119e078a655c09306e47851e15d4c0c3f9c37`. Together with locked `config.json` and `tokenizer.json`, active translator assets total **1,671,227,060 bytes**. No weights are converted or placed in an APK.

The tensor-only Candle T5 GGUF is not a llama.cpp model. The new private research library adapts the same quantized T5 API used in Pass 4 to a narrow C ABI and JNI bridge; the main Kotlin app binds a private inference Service. The same immutable Candle source archive is used, with no upstream source modification. Windows cross-compilation uses Rust 1.91.0, Android NDK 27.1.12297006/Clang targeting Android API 26, ARM64 CPU, release thin LTO, no CUDA/Metal/UG feature and no server/download client. Both Rayon and Candle pools are four threads. Android C/C++ JNI/Whisper/SentencePiece code is release optimized inside the debug APK.

All native ELF PT_LOAD segments and uncompressed APK native ZIP offsets are audited for 16 KiB compatibility. Rust/C++ linker flags set max/common page alignment to 16384. This is a packaging/static audit, not actual operation on a 16 KiB physical device. JNI marshals real UTF-8/UTF-16, including supplementary characters, rather than feeding JNI modified UTF-8 directly into Rust.

The Rust cdylib also receives explicit `-Wl,-soname,libtrial_t5.so` on Windows and Linux. CMake checks the actual ELF SONAME before importing it and records the matching imported SONAME. The version 3 S25 failure exposed the missing SONAME: the JNI ELF recorded the preparation machine's absolute library path in DT_NEEDED. Modern Android resolves path and SONAME distinctly, so an absent build-host dependency cannot load; see [Android linker changes](https://android.googlesource.com/platform/bionic/+/4f3b7e1f97b8e298a29e85e5987c30621cac0f12/android-changes-for-ndk-developers.md). No Candle/Rust runtime version or inference algorithm changes are required.

`verify-apk.py` now rejects dependency paths, mismatched SONAMEs, missing packaged dependencies and missing JNI/Rust C ABI exports. Public platform dependencies are explicitly limited to the pinned stack's Android NDK libraries; a required `libc++_shared.so` must be packaged. The four packaged ARM64 ELFs have zero unresolved strong imports against their exports and the API 26 NDK stubs. All eleven compiled Kotlin native method descriptors match the JNI function signatures. These checks establish packaging/link metadata, not successful physical inference. Safe error exports retain only allowlisted library basenames or bounded ELF symbol tokens; raw linker paths stay private.

SentencePiece's legacy full-argument FetchContent call ignores ordinary disconnect flags. `prepare-build.py` verifies the pinned SentencePiece/Abseil archives in a separate Pass 5 source cache and replaces only that acquisition stanza with a prepared-file requirement. Tokenizer source is unchanged; no Pass 2 cache/source or upstream Candle source is patched. This bounded build-only patch prevents hidden build downloads or mutable-tag substitution.

The original fixed desktop C ABI parity check completes 14 cases: 13 exact matches and one preserved es04 phrasing variation under portable desktop CPU/thin LTO. The corresponding Pass 4 worker used x86-64-v3. The original and varied outputs are recorded in preparation evidence; all phone divergences must be captured and reviewed. The model remains the exact locked representation; different CPU kernels can affect greedy token choices. The physical S25 version 5 passes standalone Whisper and isolates a native full-pipeline crash at translation start. Version 6 [corrects raw model addresses transported through JSON](CRASH_ISOLATION.md): Rust retains ownership in a mutex-protected registry, while JSON/JNI exchange only checked opaque integer IDs. Six synchronous finite stage callbacks bracket tokenization/encoder/decoder/first token. Candle kernels, pools, model/runtime pins and Whisper are unchanged. The new Windows C ABI smoke check passes the existing en01/es01 controls with exact expected outputs and verifies rejection of invalid/closed IDs and failed checkpoints. The later accepted v7 S25 review confirms both microphone directions and the prerecorded pipeline through TTS_COMPLETE; earlier crash/port receipts remain historical. See [closeout](PASS_5_CLOSEOUT.md).

The eSpeak APK SHA-256 is `741b46abf84d843f9b0cce80136f60ffee9b9fe591601b9701aa2a9ff99c9ddf`, 10,446,659 bytes. Its inspected APK reports zero requested permissions. The local-import path uses the phone's installed default TTS engine and requires installed no-network English/Spanish voices; the default may be changed to this separate research engine in phone settings. The accepted S25 v7 review identifies com.google.android.tts with offline en-US/es-US and successful direct/file playback; other phones still require their own checks. System voices are not redistributed. Corresponding source is available at the pinned [eSpeak source](https://github.com/espeak-ng/espeak-ng/tree/4870adfa25b1a32b4361592f1be8a40337c58d6c). Existing installed engines are never uninstalled to bypass signature conflicts.

Cargo.lock pins all transitive crate checksums. The [ARM64 Cargo metadata](../../tools/device-trial/evidence/cargo-licenses.json) records 138 locked packages and their declared license expressions without local paths. The external crates declare permissive open-source licenses; this metadata inventory does not replace their notices or constitute production legal approval. The [setup lock](../../tools/device-trial/setup-assets.lock.json) pins new preparation assets; inherited [Pass 4 artifact lock](../../tools/translation-quality/artifacts.lock.json) and [Pass 2 lock](../../tools/offline-feasibility/artifacts.lock.json) remain unchanged. Final APK/native library hashes and exact build requirements are generated in each build artifact's manifest/audit, never inferred from a previous build. No component/model/runtime receives production commercial approval in Pass 5.
